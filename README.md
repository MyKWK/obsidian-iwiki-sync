# iWiki Sync（Obsidian 插件）

把当前打开的笔记，手动同步到一篇**已存在**的 iWiki 文档。目前仅支持手动触发、仅支持 Obsidian 桌面端。

## 安装

1. 前往 [Releases 最新版](https://github.com/MyKWK/obsidian-iwiki-sync/releases/latest) 下载发布附件 `iwiki-sync-0.1.0.zip`。
2. 解压，得到包含 `main.js`、`manifest.json` 的 `iwiki-sync` 目录。
3. 把整个 `iwiki-sync` 目录放到你的 vault：`<vault>/.obsidian/plugins/iwiki-sync/`。
4. 回到 Obsidian，重新加载插件列表（或重启 Obsidian），在设置 → 第三方插件中启用 **iWiki Sync**。

要求：Obsidian ≥ 1.11.4，桌面端（Windows/macOS/Linux），不支持移动端。

## 配置

本插件不预置任何 MCP 服务地址，需要你自己从管理员或官方入口获取接入点，再填入设置页：

1. 打开插件设置页，在「iWiki MCP 接入点」中填入你获取到的 HTTPS 地址（例如形如 `https://<your-iwiki-mcp-host>` 的产品接口，具体以你拿到的地址为准）。
2. 在 Obsidian 的密钥管理（SecretStorage）中新增一个密钥，建议命名为 `iwiki-pat`（注意是连字符 `-`，不是下划线 `_`）；值填你的个人令牌（PAT）原文，**不要**加 `Bearer ` 前缀，**不要**加引号。
3. 回到插件设置页，在「个人令牌（PAT）」中选择该密钥，再点击「测试连接」：只会进行只读检查（确认身份、确认 `metadata`/`getDocument`/`saveDocument` 等必要工具可见），不会写入任何内容。如果缺少写权限相关工具，会明确提示"只读授权"。

`data.json` 保存接入点、密钥**名称**引用和同步基线（文档 ID、版本号、指纹、状态），不会保存令牌本身。写入结果不明时，还会暂存待核对的标题和正文；请把该文件作为本机配置保管，不要上传到代码仓库。

## 在笔记里绑定 iWiki 文档

在笔记的 frontmatter（文档属性）里加上：

```yaml
---
iwiki_url: https://iwiki.woa.com/p/1234567890  # 示例 ID，请替换成你自己的文档 ID
---
```

支持的写法：

- 完整链接 `https://iwiki.woa.com/p/<数字>`
- `https://iwiki.woa.com/pages/viewpage.action?pageId=<数字>`
- 纯数字字符串或数字，如 `1234567890`（示例 ID，请替换成你自己的文档 ID）

iWiki 的产品域名 `iwiki.woa.com` 是识别文档链接所需的固定协议格式，不代表任何真实用户或文档。不支持任意外域链接、http（非 https）、其他路径形状——这些会被当作格式错误阻止同步，但不会清除已有的本地映射。

可选属性 `iwiki_title`：

```yaml
iwiki_title: 我想要的标题
```

- 不写：同步时保留 iWiki 文档当前的远端标题。
- 写了：必须是非空字符串，否则会被阻止同步。

删除 `iwiki_url` 属性后再执行命令：插件只会清除本地记录的映射，不会触碰远端文档。

## 手动同步

打开要同步的笔记，按 `Cmd+P`（Windows/Linux 为 `Ctrl+P`）打开命令面板，运行「**同步当前笔记到 iWiki**」。

- 目标文档必须是 MD 或 DOC 类型，且当前令牌对它有编辑权限，否则会被拒绝，不创建、不删除、不改权限。
- 目标是 DOC（富文本）文档时，iWiki 会把写入的 Markdown 正文自动转换成富文本，转换结果可能与原文不完全一致；写入后插件会核对回读内容，不一致时会标记为"待核对"，不会假装同步成功。
- 首次绑定、改绑（`iwiki_url` 换成新文档）会弹出原生确认框，显示目标文档标题和类型；确认会整篇覆盖目标文档内容，点"取消"不会发出任何写入请求。
- 同一时间只允许一次同步在跑，重复点击命令会提示"正在同步中"。
- 发现远端被别人改过（版本号与上次记录不一致），会暂停并提示冲突，不覆盖。
- 写入请求超时或网络中断、结果不明时，不会自动重发；会标记为"待核对"，下次运行命令只做只读核对，核对一致才恢复正常同步。

## 故障恢复：清除卡住的本地映射

如果某篇笔记的同步状态卡在冲突或待核对，且你已经去 iWiki 核实过远端内容：

1. 先在 iWiki 上确认远端文档的当前内容是你期望的状态。
2. 在笔记的 frontmatter 中删除 `iwiki_url`，执行一次同步命令——这只会清除本地记录的映射，不会动远端文档。
3. 重新填回 `iwiki_url`，再执行同步命令。
4. 由于本地映射已被清空，这次会被当作首次绑定，重新弹出覆盖确认框，确认后才会写入。

## 当前限制

- 仅支持手动触发同步，没有自动同步、没有定时扫描。
- 不支持本地图片/附件上传，正文中的本地图片嵌入、双向链接 `[[...]]`、引用式图片、`%%...%%` 私人注释、Dataview 查询块等语法会被阻止同步并给出提示，不会被悄悄丢弃或外发。
- 不支持双向同步，不会把 iWiki 上的改动拉回 Obsidian。
- 冲突检测基于读取版本号再比较，是一种乐观检查，不是数据库意义上的原子锁；两次读取和实际写入之间仍存在无法完全消除的时间窗口。

## 从源码开发

```bash
npm ci
npm test
npm run build
```

要求 Node.js ≥ 26。构建产物是项目根目录下的 `main.js`，配合已有的 `manifest.json` 一起复制到 `<vault>/.obsidian/plugins/iwiki-sync/` 使用。
